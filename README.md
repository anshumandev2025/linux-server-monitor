# Linux Server Monitor 🖥️

A lightweight, modular Bash-based monitoring, log management, and automated backup toolkit designed for Linux servers.

---

## 📌 Overview

**Linux Server Monitor** provides essential system health tracking and maintenance automation without the overhead of heavy monitoring agents. It is designed to be easily scheduled via `cron` and integrated into production or homelab Linux environments.

### ✨ Key Features

- **System Health Monitoring (`health_check.sh`)**:
  - Captures CPU load average (`uptime`).
  - Monitors RAM and swap memory usage (`free -h`).
  - Checks filesystem storage consumption (`df -h`).
  - Triggers automated threshold alerts (e.g., warning logged when root disk usage exceeds 80%).
  - Appends timestamped reports to a centralized log file.

- **Automated Log Rotation (`log_rotate.sh`)**:
  - Monitors log file size (`du -k`).
  - Automatically archives and timestamps log files when they exceed a configurable threshold (default: 1 MB).
  - Initializes fresh log files to prevent storage exhaustion.

- **Cloud Backup Automation (`backup.sh`)**:
  - Archives critical directories into compressed tarballs (`tar -czf`).
  - Automatically syncs backups to an Amazon S3 bucket using the AWS CLI.
  - Cleans up temporary local archive files after successful upload.
  - Robust error handling with non-zero exit codes on failure.

## ⚙️ Prerequisites

Ensure your Linux server has the following packages and tools available:

- **Bash shell** (`/bin/bash`)
- **Standard Linux utilities**: `tar`, `awk`, `du`, `df`, `free`, `uptime`
- **AWS CLI** (required for `backup.sh`):
  ```bash
  # Check if AWS CLI is installed
  aws --version

  # Configure AWS credentials if needed
  aws configure
  ```

## 🚀 Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/<your-username>/linux-server-monitor.git
cd linux-server-monitor
```

### 2. Make Scripts Executable

Grant execute permissions to all scripts in the `scripts/` directory:

```bash
chmod +x scripts/*.sh
```

### 3. Configuration

Open the scripts to customize paths and thresholds according to your environment:

- **`scripts/backup.sh`**:
  ```bash
  SOURCE_DIR="/home/ubuntu/important-data"            # Directory to back up
  S3_BUCKET="s3://my-linux-server-backups-12345"    # Your target S3 bucket
  ```

- **`scripts/health_check.sh`**:
  - Default disk alert threshold is set to **80%**. Adjust `DISK_USAGE -gt 80` as needed.

- **`scripts/log_rotate.sh`**:
  - Default rotation size threshold is **1024 KB (1 MB)**. Adjust `SIZE -gt 1024` if higher capacity is desired.

## 💻 Manual Execution

Run any of the scripts directly from the repository root:

```bash
# Run system health check
./scripts/health_check.sh

# Run log rotation check
./scripts/log_rotate.sh

# Trigger immediate backup to S3
./scripts/backup.sh
```

## ⏰ Automated Scheduling with Cron

To automate monitoring, rotation, and backups, set up cron jobs with `crontab -e`:

```bash
# Open crontab editor
crontab -e
```

Add the following sample schedules (adjust paths to match your server):

```crontab
# Run health check every 15 minutes
*/15 * * * * /path/to/linux-server-monitor/scripts/health_check.sh

# Check and rotate logs daily at midnight
0 0 * * * /path/to/linux-server-monitor/scripts/log_rotate.sh

# Run backup every night at 2:00 AM
0 2 * * * /path/to/linux-server-monitor/scripts/backup.sh >> /path/to/linux-server-monitor/logs/backup.log 2>&1
```
